# Sidereal 固定开发主计划 V1.0

**冻结日期：2026-10-20**  
**性质：长期产品路线基准；不是立即执行所有阶段的指令。**  
**变更规则：仅当用户明确提出并确认“修改 Sidereal 固定主计划”时，才允许产生 V1.1 及后续版本。**

> **恢复锚点：P16 收尾 → P17 现有法学题库接入 → P18 法学资料库 → P19 题库与资料库关联 → P20 Content Studio 与主站整合 → P21 独立网站向公共站投稿 → P22 公共站审核/发布/撤回 → P23 公网部署与真实多端验收 → P24 离线同步 → P25 总验收。**

## 1. 冻结的产品目标

Sidereal 是法学学习与作品共享平台。六项长期目标不可因后来出现新材料、其他项目和临时兴趣而被替代。

1. **星空主站及阅读器**：复用同学已开发的 Three.js 星空、海面、导航、加密阅读器、Service Worker、主题和划线批注代码，不能为整合任意重写。
2. **法学题库**：以《题库-法学_v5.html》为已完成的独立题库成果，复用筛选、检索、抽题、答题判分、解析、错题、收藏、学习记录、批注和导入导出。**不重新开发现有引擎，不把其中的题目、教材、法条原文复制进公共源码仓库。**
3. **法学资料库**：对法规、讲义、教材、笔记等建立学科/专题/章节的分类、索引、检索、来源和版本标识，复用已有阅读器。
4. **Content Studio**：保留已经完成的账户隔离、草稿、附件、版本、备份、发布、回收站、用量等内容管理能力。它不是题库引擎。
5. **多站点公共作品平台**：每人保有自己的独立站点，并能以明确授权向公共站投稿；公共站负责审核、公开、更新、撤回与来源追踪，不能把“同一个 Content Studio 内发布”误当作跨站投稿。
6. **真实多设备使用**：真实 HTTPS、手机/电脑、国内网络、存储与恢复验收，在此基础上实现离线暂存及安全同步。

## 2. 开发顺序和阶段完成门槛

### P16｜编辑状态保护与冲突恢复（当前阶段）
- 完成 Dirty State、离开提示、服务器 409 版本比较，以及用户明确确认后的最新版加载。
- 以 Codex 独立代码审查、完整回归、PR/CI、合并、同步本地 main 为完成标志。
- 冻结主计划**不要求重新设计或重做 P16**；在它验收通过前不开 P17。

### P17｜已完成法学题库接入主站
- 先核实同学的主站是否已经真正接入《题库-法学_v5.html》；若已具备相同功能，则通过证据验收，不重复实现。
- 如未接入，采用最小适配让 Sidereal 用户从作品入口直接访问题库，维持既有题目筛选、判分、收藏、错题、学习状态和备份能力。
- 程序逻辑与内嵌内容在条件允许时分离；仅抽取可复用代码、数据契约和虚构测试题，**不上传受版权保护的真实题库内容**。
- 验收：从主站可进入题库，既有功能与离线数据不退化，主站解密/Service Worker 无回归。

### P18｜法学资料库的结构化分类和索引
- 为法规、讲义、教材、笔记建立统一的学科、专题/章节、资料类型、来源、版本、更新时间等元数据。
- 复用主站已实现的作品阅读、主题与划线笔记；实现按学科、类型、标题等检索，能追溯资料来源。
- 验收：用已获授权或虚构资料完成创建、查找、打开、阅读和来源定位。不能提交真实教材、密钥或私人资料。

### P19｜法学题库与资料库双向关联
- 设计题目 ID、资料 ID、章节/段落 ID 和来源关联，实现从题目跳转到对应资料，从资料查看相关题目。
- 优先利用题库已有来源字段，不改写既有题目文本或损坏用户学习记录、批注。
- 验收：双向跳转、来源不存在或版本变更时安全降级、不会误关联到其他资料。

### P20｜Content Studio 与星空主站整合
- 明确静态加密阅读器与独立后端的边界；主站有安全的内容管理入口和经过授权的公共作品浏览能力。
- 复用 Content Studio 的账户和既有 API；未发布草稿保持私有；不把密钥、服务器私有数据塞进静态主站。
- 验收：隔离测试环境中登录、退出、草稿隔离、公开作品读取和回退流程通过，原主站的作品打开和解密正常。

### P21｜独立网站向公共站传输作品
- 制定站点身份、作者授权、作品/版本标识、来源、校验、限制与安全传输协议。
- 作者主动提交作品进入**待审核**状态，不允许提交即公开；支持重复判断、失败重试与撤回申请。
- 验收：两套模拟独立站点向公共站提交作品，权限、版本与完整性边界明确；绝不上传密钥和私人资料。

### P22｜公共站审核、正式发布、更新与撤回
- 完成提交→待审核→批准/驳回→公开发布→更新或撤回流程，分开作者与审核管理权限。
- 保持版本来源与审核记录，公开内容有回退/撤回机制；不能把站内自发布当作完整审核系统。
- 验收：审核权限、驳回、修订、撤回、私有隔离与可靠性回归；主站仅展示批准的公开版本。

### P23｜实际 HTTPS 部署、跨设备及国内网络联调
- 在明确预算、托管、安全、容量与维护条件后小范围部署独立后台；验证 TLS、手机/PC、不同网络和中国大陆实际连通性。
- 必须保留同学现有线上站点，不经用户批准不购买服务、不迁移真实数据库、不替换生产部署。
- 验收：真实设备的浏览、登录、投稿、审核、发布及备份/恢复端到端报告，明确存储与网络限制。

### P24｜离线暂存及安全同步
- 基于 P23 的受控真实服务设计离线修改队列、重试、幂等、冲突呈现、附件失败处理和账号隔离。
- 禁止静默覆盖不同设备的数据，不把跨账号未同步记录混放。
- 验收：断网修改后恢复连接、并发修改、重复请求、账号切换、附件失败的自动化和真实多端回归。

### P25｜完整平台总验收
- 逐项核对题库、资料库、主站、Content Studio、独立站点投稿、审核、发布、真实联网及离线同步，完成安全、版权、隐私、恢复、性能、移动兼容和交接文档验收。
- 未完成项回到所属阶段补齐，不用新增阶段或宣传用语掩盖缺口。

## 3. 固定分工与额度纪律

- **ChatGPT**：产品设计、阶段任务书、验收口径与进度核对；维护冻结路线。
- **OpenCode 免费模型**：直接接收具体阶段实施任务，完成代码、测试和基本修复；不自行规划后续阶段或负责 PR 合并。
- **本地 Codex**：在 OpenCode 完成后集中审查、回归、批量汇总阻断点并协调返修（原则上最多两轮）、GitHub PR/CI/合并/本地 main 同步、提交报告；避免重新规划和重复读取整个仓库。
- **主站同学**：维护已完成的原主站和题库成果；独立提交现有源码差异或现状/接口文档 PR，由真实作者账号操作；与 P16 并行，不打断主线。
- **用户**：只参与高影响决策、敏感操作批准和必要里程碑主观验收。常规验收自动化完成。

## 4. 抗偏航与变更控制

1. **冻结 P16→P25 的目标、顺序、编号与完成门槛。** 新上传的文档、HTML、网页、其他项目、朋友提交、自动化建议等，默认只能给阶段提供参考或验收证据，不能自动更改路线。
2. 后来出现的新需求统一归入“候选需求池”；如果属于某阶段已定义的目标，可作为其实现细节，但不得悄悄扩大工作范围、提前新阶段或推迟原计划。
3. 用户若明确要求修改本主计划，助手须先显示修改前后对比和对进度的影响，等用户确认后才发布新版本；**普通聊天中的想法不视为变更批准**。
4. 因安全、隐私、数据损坏等重大问题，可临时止损和做最小必要修复，但不因此重新规划主线；必要时阻断阶段推进而不是跳过验收。
5. 同学若已完成某阶段范围内功能，应核验并直接采用，**只记阶段通过，不重写、不改变编号和顺序**。
6. 每阶段仅在代码审查、回归、适用 CI、PR 合并、本地 main 同步全部完成后才记为完成；不把本地开发、提交 PR 或模拟 HTTPS 算作正式上线。
7. 冻结计划与现实状态分开维护：本文件记录不可变路线，另立 `Sidereal_Stage_Progress.md` 记录最新 PR、SHA、测试结果及阻断，不能以更新进度表改写主目标。
8. 新对话继续 Sidereal 时，优先读取此冻结文件，再读取最新状态表。若与简短聊天总结冲突，以用户确认的冻结主计划作为**方向基准**，以 Git/CI/真实测试作为**完成事实基准**。
